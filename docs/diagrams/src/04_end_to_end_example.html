完整示例：登记一个新权重，并跑一次真机任务

示例一演示增量扩展（只动 JSON）；示例二用真实条目 task1 × act-v2，从敲命令一直走到日志落盘，标出每一步在哪一层、产出什么、失败时会怎样。
入口配置 编排模型 ROS 2控制硬件
示例一给 task1 增加一个新训练出的权重key、端口、GPU 均为示意值（my-new-5k、8113、GPU 7）。实际以 ss -ltn / nvidia-smi 为准。全程不需要改 shell。
1 核实路径
在 GPU 机上确认文件存在
$ ssh mac_20 'ls -d \ …/save_5000_chkpt \ …/ActionCodec-Base-RVQft \ …/state_stats.json' $ cat …/save_5000_chkpt/\ training_config.json # 读出归一化方法与 scale 字段
归一化参数要读出来，不要猜；没核实就写 unverified。
2 选端口 / GPU
避免与在跑的服务冲突
$ grep '"port"' \ config/eef_tasks.json $ ssh mac_20 'ss -ltn' $ ssh mac_20 nvidia-smi → 选 8113 / GPU 7
共用端口也合法，但同一时刻只能跑一个，切换前先 stop。
3 改 JSON
追加 model 条目 + 关联到任务
config/eef_tasks.json "tasks": { "task1": { "models": [ "act-v2", …, + "my-new-5k" ] } }, "models": { …, + "my-new-5k": { + "server": { "ssh": "mac_20", "host": "10.24.116.20", + "port": 8113, "gpu": 7, + "checkpoint": "…/save_5000_chkpt", "actioncodec": "…", + "state_stats": "…", "project": "…/Ours_VQAQ_VLA", + "script": "deploy_franka_task0_qwen_actioncodec_eef.py" }, + "action_normalization": { "method": "franka_quantile", … }, + "runtime": { "execute_horizon": 5 } } }
追加，不覆盖：不改旧 key 的 checkpoint，否则历史日志无法复现。
4 离线校验
不连任何设备
$ python3 scripts/\ validate_task_registries.py EEF registry: 26 selectable models, 0 error(s) $ ./run_eef_task.sh \ task1 my-new-5k show { "server": {"port": 8113 …
ERROR 必须修；WARN「共用端口」只是提醒。
5 交给现场
由操作者逐级上真机
$ ./run_eef_task.sh task1 \ my-new-5k dry-run $ … axis-test +z $ … run $ … stop
然后更新 docs/weights_and_tasks.md 速查表，单独提交：
config: add task1 my-new-5k

每块：  预测 15 步（15 Hz = 1 s），执行前 10 步（蓝色），丢弃后 5 步，停稳后再观测（serial）。RTC 模型会在执行中提前发出下一次观测。
8
结束三种方式
① 松开后空闲判定正常结束　② Ctrl-C　③ 另一终端 ./run_eef_task.sh task1 act-v2 stop
正常结束或故障退出时不会自动移动机械臂
任一安全层触发 → 零速停住，记 event: fault
9
stop按顺序收尾
停适配器（SIGINT）→ 停 direct 栈与相机 → 停远端 8095 服务 → 等容器退出 → fci_init.sh：夹爪 homing + 回到 config/default_initial_pose.json
用 stop-only 只停不回位
任一步停止失败 → 不执行回位
本次运行留下的日志（排查问题先看这里）
$FRANKA_LOG_ROOT/ # 默认 /media/mac/Elements1/franka_vr_docker/logs └── eef_task1_act-v2_20261113_150210_48213/ ├── selected_profile.json # 本次实际生效的完整配置 ├── dry_run/ policy.jsonl observations/ *_tmux.log ├── home/ # 仅在偏离起点时出现 └── execute/ policy.jsonl # 每块的观测、动作、event: armed / fault / complete
这几步不会被自动跳过
• 没有 axis-test 记录，direct 后端拒绝 run（第 2 步）
• 每次 run 前都会先做一次 dry-run 和握手核对（第 4、5 步）
• 不在训练起点时先 home，距离过远则拒绝（第 6 步）
• 运动模式的确认令牌由入口脚本自动设置，不要手动设置
• 急停永远是最后一道保护
